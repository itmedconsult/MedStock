## 1. หน้า Import / Check / Cut

- สร้างหน้า Import แยกจาก Dashboard ที่ `/import` และเพิ่มทางเข้าจาก Dashboard
- สร้าง `/check` และ `/cut` โดยใช้ component ร่วมกันสำหรับรูปแบบหน้าสแกนและคิว
- เพิ่ม navigation ระหว่าง Import, Check, Cut และกลับ Dashboard
- นำ workflow จากภาพ Google Sheets มาใช้: สแกน/กรอกบาร์โค้ด, เลือกสาขา, Auto Add, เพิ่มคิว, ลบรายการที่เลือก, ล้างคิว และยืนยันรายการ
- Import รองรับ Lot, Expiry และจำนวน พร้อมตรวจ SKU และบาร์โค้ดซ้ำ
- Check รองรับจำนวนที่นับจริง, Stock Type, ผลต่าง และเหตุผลเมื่อข้อมูลเปลี่ยน
- Cut รองรับ SALE/USE, ALL/PARTIAL, จำนวนที่ตัด และตรวจจำนวนคงเหลือ
- เมื่อสแกนบาร์โค้ดซ้ำ จะแจ้งเตือนและล้างช่องสแกน โดยรายการเดิมในคิวยังคงอยู่

## 2. เชื่อมการทำรายการกับ Google Sheets

เพิ่ม API ฝั่งเว็บและ Apps Script สำหรับ:

| รายการ | Action | ผลเมื่อบันทึกสำเร็จ |
| --- | --- | --- |
| Import | `importStockBatch` | เพิ่ม Inventory, เพิ่ม Log Data และเปลี่ยน BC_Registry เป็น IMPORTED |
| Check | `checkStockBatch` | อัปเดตผลตรวจนับใน Inventory และเพิ่ม Log Data |
| Cut | `cutStockBatch` | ลดจำนวน/อัปเดตสถานะใน Inventory และเพิ่ม Log Data |

- เพิ่ม action เข้า dispatcher ของระบบเดิม
- ตรวจสาขา, สินค้า, จำนวน, สถานะ และบาร์โค้ดซ้ำก่อนเขียนข้อมูล
- Import ต้องพบ Barcode ใน `BC_Registry` และมีสถานะ `ISSUED`
- เพิ่ม lock และการย้อนคืนข้อมูลเมื่อการเขียนผิดพลาดใน stock operations ทั้งนี้ยังไม่ถือเป็นหลักฐานว่าครอบคลุมความล้มเหลวทุกแบบ
- แก้ `Unsupported action` ของ Import, Check และ Cut โดยเพิ่ม handler และอัปเดต deployment
- แก้ Check ที่ถูกปฏิเสธโดย data validation ของ `Log Data` คอลัมน์ Action ให้ใช้ `CHECK STOCK`
- Cut ใช้ `SALE` หรือ `STOCK OUT` ตามเหตุผลที่เลือก

ไฟล์หลัก:

- `app/api/import/route.ts`
- `app/api/stock-operation/route.ts`
- `google-apps-script/StockOperationsApi.gs`
- `google-apps-script/README.md`

## 3. Barcode History และ Reprint

- เพิ่ม Reprint labels ในหน้า Create Barcode
- แยกประวัติตาม Thonglor / Silom / Legacy
- เลือก Batch แล้วเลือกพิมพ์ซ้ำเฉพาะฉลากที่ต้องการ
- Reprint ใช้ UUID เดิม ไม่สร้าง Inventory หรือ Running Number ใหม่
- ย้ายการจองเลขสำหรับ flow ปัจจุบันไป Google Sheets
- ใช้ `BC_Registry` เดิม พร้อมคอลัมน์ท้าย `Branch` และ `Source`
- เพิ่ม `BC_Print_Log` สำหรับผลพิมพ์รายบาร์โค้ดแบบ INITIAL / RETRY / REPRINT
- เพิ่ม actions `reserveBarcodeBatch`, `listBarcodePrintBatches`, `recordBarcodePrintAttempt`
- ใช้ ScriptLock, Request ID และ Attempt ID เพื่อป้องกันการจอง/บันทึกซ้ำฝั่ง Apps Script
- แสดงประวัติล่าสุดไม่เกิน 200 Batch ต่อสาขา
- หากบันทึกผลพิมพ์ไม่สำเร็จ เก็บ local outbox เพื่อส่ง log ซ้ำโดยไม่สั่งพิมพ์ซ้ำ
- ประวัติเก่าใน browser ไม่ถูกอัปโหลดอัตโนมัติ
- สถานะ Sent หมายถึงเครื่องพิมพ์รับคำสั่งและไม่รายงาน hardware error ไม่ได้ยืนยันว่าฉลากออกมาสมบูรณ์ทุกใบ

## 4. แก้สินค้า Import ไปอยู่แถว 1001

สิ่งที่ตรวจพบในชีต:

- Inventory มีสินค้าเดิมอยู่แถว 2–7
- รายการ `AES-004-220926-A0001` อยู่แถว 1001
- แถวระหว่างกลางดูว่างและมี dropdown เตรียมไว้
- โค้ดเดิมใช้ `getLastRow() + 1` เป็นแถวเริ่มเขียน ซึ่งไม่สะท้อนแถวสินค้าจริงในชีตนี้

แก้เป็น `medStockStockFindEmptyBlock_()` เพื่อหาช่วงแถวที่ค่าที่แสดงว่างต่อเนื่องและมีขนาดเพียงพอสำหรับ Batch ใช้กับ Inventory ตอน Import และ Log Data ของ Import/Check/Cut

Deploy Apps Script เป็น **Version 11** บน Web App deployment เดิม ยืนยันจากหน้า Manage deployments ว่าอัปเดตสำเร็จ และทดสอบ `listProducts` ได้ `ok: true`

ข้อจำกัดและงานค้าง:

- ยังไม่ได้ย้ายรายการเดิมจากแถว 1001 ไปแถว 8 ในบทสนทนานี้
- ยังไม่ได้ทดสอบ Import สำเร็จจริงเพื่อยืนยันตำแหน่งแถวหลังแก้
- การดูค่าที่แสดงว่างยังอาจเจอเซลล์ที่มีสูตรคืนค่าว่าง ควรตรวจสูตรก่อนยืนยันว่าทุกช่วงปลอดภัยต่อการเขียน
- ไม่ควรสรุปว่า dropdown หรือ format เพียงอย่างเดียวทำให้ `getLastRow()` เท่ากับ 1000; ยังไม่ได้ตรวจเนื้อหา/สูตรทุกเซลล์ที่ทำให้เกิดค่านั้น

## 5. แก้บาร์โค้ดพรีวิวไม่มีใน BC_Registry

Error ที่พบซ้ำ:

```text
Barcode was not issued in BC_Registry: AES-006-210926-A0001
```

ตรวจพบว่าหน้า Create Barcode เดิมแสดงบาร์โค้ดพรีวิวที่ browser คำนวณเอง แต่จองเลขใน Sheets เมื่อกดพิมพ์กับ Brother เท่านั้น จึงมีโอกาสสแกนรหัสที่ยังไม่ได้ลงทะเบียน หรือรหัสพรีวิวไม่ตรงกับเลขที่จองจริง

แก้หน้า Create Barcode ให้:

1. กด Generate แล้วเรียกจอง Batch ใน Google Sheets
2. แสดงบาร์โค้ดจาก UUID ที่ server ส่งกลับเท่านั้น และแสดงทุกฉลากใน Batch
3. กดพิมพ์แล้วใช้ Batch ที่จองไว้
4. หากจองไม่สำเร็จ จะไม่แสดงบาร์โค้ดให้สแกนและปุ่มพิมพ์ใช้งานไม่ได้

การแก้ใช้ร่วมกับทุก SKU ที่ระบบรองรับ แต่ไม่ได้ทดสอบครบทุก SKU

ผลทดสอบจริง:

- Generate สินค้า Restylane Volyme (Bottle CC), SKU AES-006 จำนวน 1 ฉลาก สาขา Thonglor
- ได้ Batch `BC-TL-20260922-024928-942ECD3B`
- ได้ UUID **`AES-006-220926-A0001`** วันที่ 22/09/2026
- ตรวจพบแถวใหม่ใน `BC_Registry` สถานะ `ISSUED`, Branch `Thonglor`, Source `WEB`
- สแกน UUID ใหม่นี้บนหน้า Import แล้วพบสินค้าและขึ้น `READY TO ADD`
- ยังไม่ได้กด Import stock เพื่อเขียน Inventory และยังไม่ได้สั่งพิมพ์ฉลากในการทดสอบรอบนี้

รหัสเดิม **`AES-006-210926-A0001`** กับรหัสใหม่ **`AES-006-220926-A0001`** เป็นคนละบาร์โค้ด การแก้หน้า Generate ไม่ได้ลงทะเบียนรหัสเก่าย้อนหลังให้ ผู้ใช้ยังพบ Error เพราะรูปหลังแก้ยังใช้รหัสเก่า

ข้อแก้ไขจากคำอธิบายระหว่างทำงาน: เคยแจ้งว่าจะทดสอบวันที่ 21/09/2026 แต่ผลที่จองจริงเป็นวันที่ 22/09/2026 ตามข้อมูลสินค้าที่หน้าเว็บส่งไป ต้องอ้างอิง UUID จริงข้างต้น

## 8. งานที่ยังต้องทำต่อ

1. ให้หน้า Import ตรวจ BC_Registry ก่อนขึ้น READY ปัจจุบันการตรวจบนหน้าเว็บยังไม่ยืนยันทะเบียนจริงจนส่งบันทึก
2. ทดสอบ Import บาร์โค้ดที่ลงทะเบียนแล้วจนสำเร็จ พร้อมอ่านกลับ Inventory, Log Data และ BC_Registry
3. ย้าย `AES-004-220926-A0001` จากแถว 1001 มาต่อข้อมูลเดิม หลังตรวจค่าปัจจุบันและสูตรปลายทางอีกครั้ง
4. ตรวจ `#REF!` ที่เคยพบใน Inventory!U2 และ V2 (Track Mode / Data Set); ยังไม่ได้แก้สูตรนี้
5. ปรับ lint script และเครื่องมือ lint ให้รองรับ Next.js 16
6. ทดสอบการจองหลายฉลาก/หลาย SKU, สองสาขา, การส่ง Request ID/Attempt ID ซ้ำ และ Reprint ให้ครบตามแผน
7. ตรวจ retry ฝั่งหน้า Generate เมื่อ server จองสำเร็จแต่ response ขาดหาย เพื่อไม่สร้าง Batch ใหม่โดยไม่ตั้งใจ
8. ตรวจรายละเอียด Backup/checkpoint และบันทึกวิธีกู้คืนให้ครบ
